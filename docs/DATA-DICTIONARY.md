# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 承运商换版与资格空档

两个可选列 `carrier_version`、`account` 只能追加在十个必填列之后（顺序固定、不重复）。缺列的历史批次落到 `carrier-legacy`，按基线采信，正式金额与既有样例一致。

内置版本区间（[起点,终点)）：

| 版本 | 账号 | 资格区间 | 秩 |
|---|---|---|---|
| carrier-v1 | ACCT-OLD | [不限, 2026-11-03T00:00:00Z) | 1 |
| carrier-v2 | ACCT-NEW | [2026-11-04T00:00:00Z, 不限) | 2 |
| carrier-legacy | legacy | [不限, 不限) 仅兜底 | 0 |

2026-11-03 至 11-04 为无人覆盖的**资格空档**。参数 `carrier_versions` 可覆盖区间，`verified_scans` 列出质控已核验的扫描号。

裁定规则：

- 同一包裹、同一节点、同一发生时刻被新旧账号重复回传时，折叠为一条计时事件，高版本账号优先；被取代那条以 `superseded` 保留原件来源行。
- 空档或换版后旧账号来源：事件仍进入时效计时并产生 `provisional_expected`（运营不等），但 `expected` 记 0，结算裁定为「待核验挂账」，对账不判通过。
- 已核验来源（`verified_scans`）转为「正式可结算」，正式金额才等于暂算金额。
- 每个包裹输出 `qualification_interval`（采用版本区间 + 命中的空档窗口）与 `non_adopted_reason`（逐条未采用原因及版本区间）。
- 页面「结算裁定」表、`/api/settlements` 与导出 CSV 读取同一份 m6 结果，不做二次推导。

换版 `POST /api/runs/<id>/switch`：在单个事务内写结算快照（`settlements`）、换版记录（`switches`）并切换 `carrier_state`；任何一步失败整体回滚，旧版结算与生效批次保持原样。同一批次重复提交只读回原快照，不重复记账、不改正式金额。同源重跑 `POST /api/runs` 复用已有批次，不新增记录。
